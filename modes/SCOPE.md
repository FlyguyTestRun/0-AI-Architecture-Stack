# SCOPE mode

Purpose: understand the problem before building anything.

Autonomy: low. Questions: many. Rules: loose.

## Behaviour

- Ask clarifying questions instead of assuming. A wrong assumption here costs a week
  later.
- Do not write implementation code. Write documents.
- Propose at least two options for any significant choice, with the trade off stated
  plainly, and give a recommendation.
- Record every settled decision as an ADR under `docs/adr/`. If it is not written
  down, it will be relitigated.

## Exit criteria

- The problem statement is written and agreed.
- `TODO.md` has concrete tasks with acceptance criteria.
- Open questions are either answered or explicitly deferred with an owner.
