# CLAUDE.md, operating rules for this repository

Read at the start of every session. These rules are not optional.

Last updated: 2026-08-24

---

## What this repository is

A zero cost AI architecture baseline. It is a starting point that gets copied into
client and product repositories, so the standard here is higher than for a normal
project: anything sloppy gets multiplied across every project built on it.

Read `ARCHITECTURE.md` before changing anything structural. Read `TODO.md` for the
current work queue.

---

## Hard rules

**No AI attribution, anywhere. (ADR GLOBAL-001)**

- No `Co-Authored-By: Claude` or any equivalent trailer in a commit message.
- No "Generated by Claude", "Generated with Claude Code", or robot emoji banners in
  any file, pull request body, or code comment.
- The pre-commit hook blocks the common patterns. Do not work around it.

The rule bans *attribution*, that is, any claim that an AI wrote this work. It does
not ban naming an AI tool as a component of the system. Layer 6 of the architecture
is a code agent, and `mcp.json` uses a documented third party configuration format,
so those products are named in `README.md`, `ARCHITECTURE.md` and `docs/adr/`. That is
product documentation, not a byline. If a mention would read as "an AI produced this
repository", remove it.

**No em dashes. (ADR GLOBAL-003)**

- The em dash (U+2014) is a visible AI writing pattern. So are the en dash (U+2013)
  and the horizontal bar (U+2015).
- Replace with a comma, a colon, a period, or restructure the sentence.
- `scripts/check_emdash.py` enforces this. It runs in the pre-commit hook and in CI.

**Approval before committing. (ADR GLOBAL-002)**

- Show `git diff --stat` and wait for an explicit "commit it" or equivalent.
- Exception: when the session was opened with a standing instruction to work
  autonomously, commit and push without asking, then report what was pushed.

**No large refactors without approval.**

- A large refactor is more than two files changed, or any structural change: new
  directories, moves, deletions.
- Show the change list first, get agreement, then execute.

**Never break the offline path.**

- Every layer must keep working with no Docker, no model server and no network.
- Any new dependency belongs in an optional extra in `pyproject.toml`, never in the
  base `dependencies` list, unless the offline path genuinely requires it.
- `make check` must pass on a machine with no services running. CI enforces this.

## Session start checklist

1. `git pull`
2. Read this file.
3. Read `TODO.md` for the current queue and the active mode.
4. Run `make check` to confirm a green baseline before changing anything.

## Session end checklist

1. `make check` passes.
2. `TODO.md` reflects what actually happened, including anything left unfinished.
3. Add an ADR under `docs/adr/` for any decision that future work should not relitigate.
4. Commit and push.

## Operational modes

Work happens in one of six modes. The mode sets how much to ask and how much to
assume. Switch by saying "enter BUILD mode". The active mode is recorded at the top
of `TODO.md`.

| Mode | Autonomy | Questions | Rules | Use when |
|------|----------|-----------|-------|----------|
| SCOPE | Low | Many | Loose | Requirements are unclear |
| BUILD | High | Few | Medium | Requirements are settled, ship features |
| SECURE | Medium | Some | Tight | Adding auth, validation, hardening |
| TEST | High | Few | Tight | Writing tests, closing coverage gaps |
| FIX | Medium | Some | Medium | Debugging a specific defect |
| DEPLOY | Low | Many | Strict | Packaging and releasing |

Full definitions are in `modes/`.

## Code standards

- Python 3.11 or newer. Type hints on every public function.
- Every layer exposes a `Protocol` and at least one implementation that runs offline.
- Docstrings explain **why**, not what. If a comment restates the code, delete it.
- Tests must not require network, Docker, or a model server.
- `ruff check` and `ruff format` must both pass. Run `make fmt` before committing.

## Layer boundaries

The dependency direction is strict. A layer may import from the layers below it and
never from the layers above.

    frontend / api / cli
        depends on -> app.ZerostackApp
            depends on -> orchestrator -> {llm, rag, tools}
                all depend on -> config, observability

If a change needs the orchestrator to know about the API, the design is wrong.
